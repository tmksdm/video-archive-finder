# Базовое измерение скорости поиска

## Критерий этапа 3

Для локального SQLite-индекса из 100 000 папок после прогрева:

- конфигурация: Release, x64;
- отображаемая выдача: не более 200 совпадений;
- количество прогревов: 3;
- количество измерений: 15;
- допустимый показатель: p95 не более 100 мс.

Порог относится к `SqliteFolderSearchService` и не является
универсальной гарантией для любого компьютера.

## Команда

```powershell
dotnet run --project .\tools\VideoArchiveFinder.SearchBenchmark -c Release
```

Инструмент создаёт отдельную временную SQLite-базу в `%TEMP%`,
не обращается к видеоархиву и удаляет базу после завершения.

Для измерения построения папочного индекса реального архива:

```powershell
dotnet run --project .\tools\VideoArchiveFinder.SearchBenchmark `
    -c Release -- --archive "<путь-к-архиву>"
```

Этот режим читает только дерево папок, не запускает FFprobe и не создаёт
миниатюры. Путь не сохраняется в исходном коде, временная база удаляется.

## Вывод

Все измеренные сценарии укладываются в принятый порог p95 100 мс.

Текущую реализацию SQLite-поиска через `instr` можно оставить
без оптимизации на этапе 3.

Повторно рассмотреть оптимизацию необходимо, если:

- p95 на 100 000 папок превысит 100 мс;
- рабочий индекс существенно превысит 100 000 папок;
- измерение полного UI-сценария выявит заметную задержку;
- появятся новые поля или режимы поиска.
