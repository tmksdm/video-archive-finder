## Ограничения и блокеры

1. **CHANGE-STOP реагирует на любой commit**, включая метаданные, миниатюры
   и `LastSeenUtc` при обычном просмотре папки. После просмотра может потребоваться
   «Обновить поиск» с первой порции. При неизменном индексе доступны все результаты.
   Более точный result-relevant stamp требует отдельного решения; исключать
   «свои» commits или полагаться на COUNT/MAX небезопасно.
2. **Latency-бюджет p95 100 мс не выполнен на 376 342 видео.** Первая порция
   p95 3 784,06 / 2 088,36 мс для двух сценариев, последующие около секунды.
   Это SQL/точный COUNT, не UI-stall. Нужна отдельная оптимизация без незаметного
   изменения схемы/семантики. Холодный кэш ОС не измерялся.
3. Не проверены отдельная Windows без .NET/VLC, разные DPI/разрешения и
   реальный OS drag-and-drop в Premiere для нового пакета.
4. Долги индексации из раздела 9 аудита не включены в эту задачу и не устранены.
5. Off-UI освобождение адресно охватывает две существующие очереди. Если появятся
   новые sync-over-async `Dispose`, требуется проверить их жизненный цикл,
   особенно закрытие при реально занятой очереди, а не только пустом индексе.
